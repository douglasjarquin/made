18:	return defaultSocketPath(home, SessionName)

     /Users/douglasjarquin/.config/herdr/herdr.sock
   and 'herdr pane list --session made' itself resolves session sockets to yet
   a THIRD, different path (confirmed by its own real error output below).

3) No 'made' session was ever attached/running (a human/interactive
   'herdr --session made' or 'herdr session attach made' is what actually
   creates a session's pane socket - nothing in made's own push-to-pipeline
   flow does this), confirmed by real output:
{"id":"cli:pane:list","error":{"code":"server_not_running","message":"no herdr server is running at /Users/douglasjarquin/.config/herdr/sessions/made/herdr.sock; run `herdr session attach made` to start or attach it"}}

None of these three issues are made-repo bugs to fix as part of this
verification pass (out of scope, read-only verification) - they are
environment/version-skew findings worth flagging: in THIS environment,
made's herdr Visibility.Open() can only ever take its no-op fail-open
path, never its real-pane-opens happy path, for three independent
reasons outside made's control. That said, this is exactly the
fail-open contract internal/pipeline/herdrview.go documents and is
designed to guarantee - it worked exactly as designed below.
