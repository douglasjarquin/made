Description:
TestRunManager_UpdateStagesVisibleViaSnapshot and
TestRunManager_UpdatePendingFindingsVisibleViaSnapshot
(internal/daemon/runstate_test.go) submit a run, call
RunManager.UpdateStages/UpdatePendingFindings with real data, and assert the
SAME data is visible via a subsequent RunManager.Snapshot call (and via
RunManager.List, per TestRunManager_UpdateStagesReflectsListToo).

TestStatusJSON_ReflectsRealStageUpdate (cmd/made/status_test.go) is the full
end-to-end scenario required by this task: it starts a real daemon
(in-process, real Unix socket via startDaemon, same harness as the existing
TestStatusJSON_SchemaValidity), submits a run via RunManager.Submit, calls
RunManager.UpdateStages with

  []daemon.StageResult{
    {Name: "intent", Result: "pass"},
    {Name: "rebase", Result: "pass"},
    {Name: "review", Result: "pending"},
  }

and RunManager.UpdatePendingFindings with

  []daemon.AskUserFinding{
    {Stage: "review", Message: "Should this helper be exported?"},
  }

then invokes the real `made status --json run-real-stage-1` CLI path over the
socket (runCapture -> run(["status","--json","run-real-stage-1"], ...)),
exactly the code path a user's shell invocation exercises, and asserts the
decoded StatusReport.Stages/PendingFindings match those real values exactly -
not the old hardcoded placeholder (all-9-stages-"pending", empty findings).
