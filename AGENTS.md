# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Add durable project-specific notes here as they are discovered through real work.

- The versioned runtime contract is implemented at `cmd/made/runcommands.go` and `internal/daemon`; validate it through `made capabilities --json` and the `made run ... --json` commands.
- Config lives at `.made.yaml` or `.made/config.yaml` (equally valid, conflict if both present); legacy root `.made.yml` still works during a bounded deprecation window. All three are decoded strictly with `version: 1`. The sole discovery entry point is `config.Locate` in `internal/config/locate.go`; the loader is `internal/config/file.go`.
- Reviewer harnesses (`internal/agent/agent.go`'s `Kind`: `codex`, `claude`, `cursor`, `grok`) share one task text and one findings schema (`reviewSchema` in `internal/agent/spawn.go`); per-CLI argv and response-envelope parsing live in `invocation`/`extractStructuredResponse` there. Codex's and Claude's strict structured-output modes reject any schema property not listed in `required`, so every finding property is required and the semantically optional ones (`code`, `class`, `symbol`) are nullable - never add an optional-but-not-required property. `cursor-agent` has no schema flag and concatenates all assistant text into `result`, so its adapter appends the schema to the task and takes the trailing JSON object. On Linux, `internal/agent/containment.go` ro-binds `/` but binds each harness's own HOME state directories (`Kind.stateDirs`, e.g. `~/.claude`, `~/.cursor`, `~/.grok`, `~/.codex`) writable, because every CLI persists session state per turn and fails closed otherwise; the candidate source mask is applied after those binds so it wins. `internal/agent/testdata/fakeagent` doubles all four (`FAKE_AGENT_KIND`) and writes into `~/.<kind>` when that directory exists, so a broken containment profile fails the double too; `MADE_AGENT_LIVE_TEST=codex,claude,cursor,grok go test ./internal/agent -run TestLive_` drives the real, authenticated CLIs.
- Local git fixtures can inherit SSH commit signing from the host; use process-local `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=commit.gpgsign GIT_CONFIG_VALUE_0=false` when running the Go test suite.
- `made validate --managed --json-events` (`internal/managed`) is a generic, short-lived, daemonless validation engine for one exact input SHA - see `docs/managed-validation-v1.md` and `docs/managed-validation-integration.md`. It derives a policy-only stage plan (`internal/managed/stageplan.go`) before running anything: Review/Test/Document/Lint each resolve to `run`, `not_configured`, or `disabled`, and a plan with no `run` stage fails as `infrastructure_error` rather than a meaningless pass. Review is obtained through a `ReviewSource` (`internal/managed/reviewsource.go`): `internal` spawns Made's own agent in report-only mode, `external` accepts one caller-supplied result validated by `internal/managed/externalreview.go` against `internal/managed/contractreview.go`'s canonical, hash-bound review contract - both sources feed the same finding/fingerprint/Decision classification path in `internal/managed/runner.go`. It is daemonless and can never push, create a PR, poll CI, or merge; those remain the standalone daemon-backed pipeline's job (unchanged, see `internal/orchestrator`). `Runner.Run` (`internal/managed/runner.go`) seeds every planned stage's `StageResults` entry up front (`initialStageResults`) before executing any of them, so a stage planned to `run` that Run never reaches (an earlier stage already returned a non-pass outcome) stays visible at `pending` in `stage_results`/`terminal.json` instead of being silently dropped; `TerminalManifest.SchemaVersion` (`internal/managed/evidence.go`, currently 3) versions that shape and is independent of the JSONL event envelope's own `SchemaVersion` (`internal/managed/contract.go`, currently 1, unchanged by this). Project issue #61 wired issue #33's lane-command reuse (previously daemon-backed-pipeline-only, see `internal/orchestrator/lanecommands.go`) into this same engine, read-only: `internal/managed/stageplan.go`'s `laneExtraCommands` builds each selected lane's Full-command `receipt.Fingerprint` via the shared `receipt.BuildLaneFingerprint`/`receipt.RepoIdentity` (same helpers the daemon-backed pipeline uses, so a receipt published by either path is found by both) and calls `receipt.Store.Get` (local-refs-only, never fetches) - a hit moves that command from `StagePlanEntry.TestExtras` to `TestReused` instead of executing it, surfaced on `StageResult.ReusedCommands` and, for `made verify`, `StageReceipt.Reused`. **`internal/managed` and `internal/verify` must never call `receipt.Store.Put`** - publishing a receipt remains exclusively the daemon-backed pipeline's job; reuse here is opportunistic and fails open to real execution on any cache miss or fingerprint mismatch. Honors the same `validation.no_reuse`/per-lane `no_reuse` config switches as the daemon-backed pipeline - no separate flag. `cmd/made/lanereuse_safety_test.go` proves the no-`Put`/no-`git push` invariant with a git-argv spy across both a fresh cache-miss and a real reuse hit.
- `review.guides` (project issue #40, `internal/config/config.go`'s `Review.Guides`) lets a project point Review at zero or more trusted, repository-relative guide files (a feature map is the recommended convention, not a dedicated subsystem). Managed mode resolves and hashes them from the trusted root in `internal/managed/guides.go` (`TrustedGuideRoot`/`ResolveTrustedGuides`) before Review runs, and binds path/hash/bytes into `ReviewContract.Guides` (`internal/managed/contractreview.go`) so its hash changes whenever a guide's order, path, or content changes. Both `InternalReviewSource` (via `internal/pipeline/review` and `internal/agent`'s `ReviewGuideRef`/`ReviewGuide`) and `ExternalReviewSource` receive the identical guide list; an external result may optionally echo bounded `guides_consulted` metadata, validated in `internal/managed/externalreview.go`.
- `made verify` (project issue #41, `internal/verify` + `cmd/made/verify.go`) is a friendlier, daemonless command surface over `internal/managed`'s engine for validating one committed change - no gate, daemon, push, PR, or CI polling. `made verify [run]` is the internal one-shot; `made verify prepare`/`made verify complete` split external review into two short-lived invocations around a bounded, hash-bound request file (`internal/verify/request.go`); `made verify status`/`receipt`/`clean` inspect a local, non-pushed receipt store (`internal/verify/receipt.go`). It resolves `base_sha` as `merge-base(--base-ref, HEAD)` locally only (never fetches) and discovers trusted config via `config.Locate` on the current worktree - **V1 simplification**: unlike the daemon-backed gate's git-ref-based trusted/candidate separation, `made verify` treats the current worktree's discovered config as trusted policy directly (there is no daemon here to extract a trusted base at a different ref); this is a deliberate, documented V1 limitation, not an oversight. Its own temporary state (requests/evidence/receipts) lives under `os.UserCacheDir()/made/verify/<hash of repo root>`, never inside the repository's `.made/` or `.git/` (the latter would also fail `internal/managed`'s own evidence-dir-outside-workspace preflight check). `verify.Receipt`'s `schema_version` (currently 3, `internal/verify/receipt.go`) is its own version space, unrelated to `internal/managed`'s `TerminalManifestSchemaVersion`; `ReceiptStore.Get` hard-rejects any other value with no migration path, by design - a cached receipt in `~/.cache/made/verify/` from before a bump simply becomes unreadable. `RunEngine` calls `managed.BuildStagePlan`/`managed.Runner` directly (see the reuse note on the `made validate --managed` entry above) so lane-command reuse is wired exactly once, in `internal/managed`, and `made verify` inherits it with no separate logic. `Receipt.EvidenceDir` is the per-invocation evidence directory (`ManagedEvidenceStore.InvocationDir()`, where `terminal.json` actually lives), never the shared evidence root. `run`/`prepare`/`complete --json` route every pre-`Outcome` failure (config-locate/`ConflictError`, guide resolution, HEAD-moved, worktree-dirty, stale request/contract, etc.) through `cmd/made/verify.go`'s `failVerify`, which keeps the human-mode stderr line unchanged but also always writes a `{"error", "exit_code"}` JSON envelope to stdout when `--json` was passed, at `managed.OutcomeInfrastructureError.ExitCode()` - distinct from `Outcome.ExitCode()` on an already-constructed `Outcome` (issue #43 Task 9), which `emitJSON` already handles.
- `made cursor init/sync/check/doctor` (project issue #42, `internal/cursor` + `cmd/made/cursor.go`) generates and maintains two project-local Cursor projections from trusted config - `.cursor/agents/made-reviewer.md` (only when `review.executors.cursor.model` is configured; its frontmatter carries that exact model, never `inherit`) and `.cursor/skills/verify-with-made/SKILL.md` (always, config-independent) - so a Cursor Cloud agent can drive `made verify prepare`/`complete` (issue #41) itself with no Made-launched daemon, gate, or review harness. Every generated file carries a marker (`cursor.GeneratedMarker`); `internal/cursor/write.go` refuses to overwrite an unmarked (unmanaged) file unless `--adopt` is passed, and `sync` removes a Made-owned reviewer file if the model is later unset. `Config.Review.Executors.Cursor.Model` (`internal/config/config.go`) is a bounded, single-line, opaque preference only - Made never rejects a Review result over a substituted or missing model. This project's own `.cursor/agents/made-reviewer.md` and `.cursor/skills/verify-with-made/SKILL.md` are committed and generator-derived: editing `internal/cursor/skill.go`/`reviewer.go` or `.made.yaml`'s cursor/guide config requires re-running `made cursor sync` at repo root and committing the result, or `internal/cursor/committed_test.go`'s `TestCommittedCursorProjectionsMatchGenerator` (using the same `Check` drift detector as `made cursor check`) fails CI. `internal/cursor/doctor.go`'s `base_ref` check caps at `warn`, never the fatal status, when the ref can't be resolved locally (a shallow/limited Cloud VM clone is a real, survivable condition); the skill's step 4 branches on the `cursor_executor` check's `detail` field (`configured`/`not_configured`), not `status` (always `ok`/`warn`/`skipped`), and treats `status: warn` (review required, no model configured) as a hard stop. Doctor's `cursor_model` check validates with `Config.ValidateWithoutReviewAgentRequirement()`, the same relaxed pass `config.ParseBytes`/managed/verify already use - never the stricter `Config.Validate()`, which would false-negative a valid Cursor-external-only config (`review.required: true`, a configured `review.executors.cursor.model`, no top-level `agent`) since that combination is exactly what an external `ReviewSource` is for. `scripts/install-cursor-cloud.sh` is the interim installer (issue #27 is the release path) that a Cloud Build uses to put a pinned `made` (`-X internal/managed.MadeVersion=<sha>`) and CI's `golangci-lint` on PATH.
- Cursor Cloud for this repository is `.cursor/environment.json` plus `docker/dev/Dockerfile` (repo-root context). The Build `install` runs `scripts/install-cursor-cloud.sh`; do not re-run the installer from a skill invocation.
